# FootPulse

Минималистичный футбольный портал на React + TypeScript + Vite. Приоритет — читаемость, реальные источники и явное обозначение границ данных.

## Реализовано

- Минималистичный чёрно-белый интерфейс с красным акцентом, адаптированный под телефон.
- OpenLigaDB: матчи, результаты и выбор турнира/сезона через публичный API без ключа.
- StatsBomb Open Data: матчи чемпионата мира 2022 года и загрузка событий выбранного матча (удары, голы, передачи, замены и доступные поля событий) из открытого репозитория.
- Поиск по загруженным матчам и командам; поиск по игрокам ограничен данными, доступными в текущем наборе событий, и пока не является глобальным каталогом игроков.
- Явные состояния загрузки/ошибки, атрибуция источников, без вымышленных результатов.
- Начальная схема PostgreSQL находится в `database/migrations/001_initial.sql`.

## Источники и ограничения бесплатного доступа

1. **OpenLigaDB** — публичный API результатов и матчей, особенно покрытие немецких турниров. [Сайт](https://www.openligadb.de/).
2. **StatsBomb Open Data** — открытые события для опубликованных соревнований и сезонов; текущий подключённый набор — ЧМ-2022. [Репозиторий и условия](https://github.com/statsbomb/open-data).
3. **football-data.co.uk** — бесплатные CSV-архивы исторических результатов и статистики, указаны в каталоге как следующий источник для серверного импорта. [Сайт](https://www.football-data.co.uk/).
4. **Wikidata** — справочные сведения о командах, людях и соревнованиях; требует отдельного SPARQL-адаптера. [Сайт](https://www.wikidata.org/).

«Бесплатно» не означает универсальное покрытие, отсутствие лимитов или разрешение на любое повторное распространение. Не следует выдавать источник за полную базу всех матчей и игроков. Перед серверным импортом нужно проверять условия использования, атрибуцию, лимиты и права на повторную публикацию.

## Запуск

Требуется Node.js 20+ и npm.

```sh
npm install
npm run dev:web
```

Сборка веб-клиента: `npm run build --workspace @footpulse/web`.

## База данных

Схема PostgreSQL — `database/migrations/001_initial.sql`. Наличие схемы само по себе не означает, что база развёрнута или заполнена. Для исторического архива и глобального поиска необходимы PostgreSQL, серверный API и отдельная задача импорта с кешированием, дедупликацией, логированием источника и временем обновления.
